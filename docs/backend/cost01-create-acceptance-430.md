# COST01-OP02 — قبول إجراء جديد ضمن عقد الإنشاء الحالي

القضية [#430](https://github.com/ameenalqershi/wow-erp/issues/430). المصادر: [تحليل COST01](../../muhaseb-erp-analysis/docs/modules/COST.md)، [الحقول](../../muhaseb-erp-analysis/data/fields.csv)، [المخطط](../../muhaseb-erp-analysis/diagrams/source/module-COST.mmd)، [مصفوفة التنفيذ](fields-implementation.csv).

- POST /companies/{companyId}/cost-centers: هوية وشركة من الخادم، رمز واسم عربي إلزاميان، اسم إنجليزي وملاحظات وأب وفرع ومسؤول اختياريون في العقد الحالي؛ بطاقة جديدة فعالة بإصدار 1. F01–F05 وF07–F10، F06 وحالة الإنشاء؛ F12–F15 عبر الإصدار والتدقيق. لا ادعاء بإتاحة F11.
- اختبارات FG01 المدمجة في #2938 تثبت حفظ الهوية والرمز النصي والاسم العربي والتفرد داخل الشركة والتزامن وإعادة الطلب عبر المجال وSQL وHTTPS/JWT. اختبارات FG02 وحارس الشجرة القائمة تثبت سلامة المراجع والحالة.
- الإضافة: فشل الحفظ قبل الالتزام يعيد البطاقة والتدقيق والإيصال؛ إعادة المحاولة بالمفتاح نفسه تحفظ بطاقة واحدة وحدثًا وإيصالًا واحدين؛ الإنشاء لا ينشئ قيدًا أو حركة مخزون. SQL يتحقق من العدد قبل وبعد ومن المراجع والقيم المحفوظة.
- الإنشاء الحالي لا يقدم شاشة UI أو قيم نوع المركز F11 غير المحددة (القضية #427). لا إغلاق تلقائي قبل مراجعة قبول نطاق القضية والقيد المرتبط بالحقل الإلزامي. لا تعديل للمصدر أو الترحيلات أو API.

القبول النهائي مشروط بـ CI. التبعية اللاحقة للموازنات والتوزيعات موثقة في #428، ولا تغيّر دلالة إنشاء البطاقة الحالية.
