# COST01-FG02 / OP04 — قبول حقول البطاقة وتعطيل المركز

القضيتان [#424](https://github.com/ameenalqershi/wow-erp/issues/424) و[#432](https://github.com/ameenalqershi/wow-erp/issues/432). المرجع: [مواصفة COST01](../../muhaseb-erp-analysis/docs/modules/COST.md)، [قاموس الحقول](../../muhaseb-erp-analysis/data/fields.csv)، [خريطة الوحدة](../../muhaseb-erp-analysis/diagrams/source/module-COST.mmd)، [مصفوفة التنفيذ](fields-implementation.csv).

| الحقل | الربط |
|---|---|
| F05 الاسم الإنجليزي | EnglishName نص Unicode اختياري، حتى 200 محرف |
| F06 فعال | IsActive قيمة منطقية؛ نعم للبطاقة الجديدة؛ POST status يطلب قيمة صريحة وإصدارًا وسببًا |
| F07 ملاحظات | Notes نص Unicode اختياري، حتى 2000 محرف |
| F08 المركز الأب | ParentId اختياري؛ مرجع فعال في الشركة والنطاق؛ منع الدورات |
| OP04 تعطيل | إجراء مستقل عن الحذف؛ يحفظ البطاقة ومرجعها وتاريخها |

اختبارات CostCenterTests تثبت القيم الاختيارية، حفظ النصوص والعلاقة وتغييرها، رفض تعطيل الأب ذي أبناء فعالين، رفض مرجع خارج النطاق، rollback وتكرار الطلب ورفض الإصدار القديم والفاعل غير المخول. اختبارات FoundationSqlIntegration تثبت حفظ Unicode والأب والحالة، قبول عملية واحدة فقط من طلبين متنافسين بالإصدار نفسه، إعادة الطلب المقبول دون تكرار الأثر، وعدم حفظ تدقيق أو إيصال للرفض. اختبارات HostedApiIntegration تثبت إلزام Boolean صريح، رفض تعطيل الأب الفعال ذي ابن فعال، وثبات الإصدار والحقول بعد التعطيل. الحماية التاريخية والقيود المالية مغطاة أيضًا بالاختبارات القائمة.

لا تغيير لمصدر التحليل أو API أو SQL. التحقق من عرض النصوص بأمان في واجهة المستخدم خارج نطاق backend؛ الشاشة الأم تظل جزئية ولا تُعد F11 أو الموازنات مكتملة. القبول النهائي مشروط بنجاح CI.
