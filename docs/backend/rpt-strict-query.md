# RPT01/RPT02 — strict report query (#2949)

Original [screen contracts](../../muhaseb-erp-analysis/docs/modules/RPT.md), [navigation](../../muhaseb-erp-analysis/diagrams/source/module-RPT.mmd), [fields](../../muhaseb-erp-analysis/data/fields.csv), and [report contract](../../muhaseb-erp-analysis/docs/08-reports-and-roadmap.md) require the report output to reflect the authorized, selected filters (BR02/BR18). Unsupported currency/state/detail/range filters must not silently produce default results.

Seven current routes (RPT01 display/print/export/drilldown; RPT02 single account/range/print) use a shared endpoint filter deriving allowed keys and multiplicity directly from explicitly bound FromQuery parameters. Unknown query keys and repeated scalar values, including case variants, return 422 problem+json before invoking the report service. Repeated branchIds remain supported; malformed typed parameters retain ASP.NET's 400 binding response. Existing authorization and accounting filters are unchanged. No new currency policy, no new data permissions, no schema change and no claim of completed screen. Adding a future supported field requires an explicit FromQuery binding and actual service implementation; the guard accepts that declared parameter without a second allowlist.

Evidence: local test HTTP integration, production SQL/HTTPS/JWT integration on all seven routes, no extraction/audit effects for rejected calls, OpenAPI 422 contract; existing multi-branch positive cases remain regression gates. This rejection invariant is independent of which future modes are eventually approved.
