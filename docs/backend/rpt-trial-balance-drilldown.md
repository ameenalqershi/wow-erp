# RPT01-OP03 — source drilldown (#2042)

Original [screen](../../muhaseb-erp-analysis/docs/modules/RPT.md), [fields](../../muhaseb-erp-analysis/data/fields.csv), report contract and BR02/BR18. Use GET /api/v1/companies/{companyId}/reports/trial-balance/{accountId}/drilldown with the same from/to, branchId or branchIds, costCenterId, accountLevel and showZero as the displayed report. The response contains the selected summary row, summaryAccountLevel, and detail using the existing TrialBalanceResult shape (accountLevel null, posting leaves only). Both summary and detail use the same materialized journal set. For each detail account call the existing RPT02 account ledger with identical dates, branches and center, then JournalId/Position to GL03 as documented in rpt-ledger-source-drilldown.md.

A grouped row nets opening and closing balances: compare signed opening and closing totals, not gross debit/credit of its leaves; movement debit and credit reconcile separately. Only rows visible at the requested level may be drilled; nonexistent or hidden row yields 404, invalid date or level 422, unauthorized scope 403. Read-only, no new schema or accounting policy. Tests cover nested hierarchy, leaf, invalid/hidden rows, branch scope, real SQL-backed HTTPS/JWT, OpenAPI and ledger reconciliation. Separate calls may observe newer postings; no cross-request immutable snapshot is claimed. Other RPT01 gaps remain open.
